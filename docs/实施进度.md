## 当前容量边界

- 每文件最大 64 MiB，单行最大 8 MiB，每会话最多 100,000 条不同 ID。
- 最多同时打开 4 个会话，保留的原始记录合计不超过 128 MiB；这是原文预算，进程总内存还包含索引、摘要与解析临时内存。
- 上限触发时拒绝本次导入，不静默截断；正常坏行跳过并计数。会话提交成功前不替换已有数据。
- 原始记录行用于导出，保留未知字段、重复 JSON key、长整数和高精度小数；换行统一为 LF，空行、坏行与旧版重复 ID 记录不再导出。
- 自有诊断序号初始约定为规范的 uint64 十进制字符串；此阶段仅校验事件契约，不监听设备或接收日志。

## 2026-11-13 本机验证

- 环境：Apple M3 Pro、18 GiB RAM，macOS 27.2.1（26B131），WebKit 22625 / 22625.2.8.11.9，Rust 1.91.1，Node 25.9.0，pnpm 10.33.0。探针和原生应用使用 debug 构建。
- TypeScript、7 项前端测试、9 项 Rust 测试、Rust 格式与 Clippy `-D warnings`、前端构建和 macOS `.app` 编译通过。
- 官方 `basic.peek` 原生导入 18 条，错误过滤得到 6 条；通过 Cmd S 保存后与输入逐字节一致（20,340 字节）。重复 `Set-Cookie` 保持两行，响应树支持非 ASCII 文本。
- 合成输入：100,000 条，39,999,203 文件字节，原文预算计 39,899,202 字节，0 跳过。初始 AX 树仅呈现约 33 行；End 到第 100,000 条、Home 返回第 1 条，两端详情正确。实际 JSON 树完整显示 `900719925474099312345` 与 `0.12345678901234567890`。
- Rust 核心单次导入 4,157.09 ms；搜索 `records/99` 的 20 次窗口查询 P50 33.67 ms、P95 45.78 ms。此数据仅为本机 debug 核心探针，未测 WebView 帧率、实时吞吐、IPC 延迟或进程峰值内存，不作为完整性能验收。
- 复现：`node scripts/generate-session.mjs <新路径.peek> 100000`，再用桌面打开，或运行 `cargo run --locked --manifest-path src-tauri/Cargo.toml --example session_probe -- <路径.peek>`。生成脚本拒绝覆盖已有文件，输入均为合成数据。
- JSON 编辑器懒加载 chunk 约 1 MiB，Vite 仍提示大包；后续需继续评估组件拆分与目标 WebView 开销。

## 归档 v1

- 归档为 ZIP，包含 `manifest.json`、`network/0.peek` 等网络文件、`diagnostics/0.jsonl` 等诊断文件；manifest 包含容器版本、网络/诊断版本、各成员 SHA-256、字节数、条数及网络关联与保留计数。不会归档配对 token。
- “保存完整归档”保存当前网络会话及其绑定诊断运行，或当前独立诊断运行；不受列表搜索、分组和时间过滤影响，只包含当前实际保留的数据。已淘汰的正文/日志不凭空补全，尚未取回的 remote 正文保持未加载。保存时还在同步的网络快照会标记该状态。
- 网络与诊断原始记录保留长数字、未知字段、重复 JSON key 和堆栈；LF 换行。ZIP 写入临时文件并 fsync，成功后原子替换；错误不破坏原文件。
- 导入先完整校验，容量不足或任一成员损坏时整组失败。成员名严格匹配约定，不解压到文件系统；拒绝多余/重复成员、未来版本、校验和不匹配、绑定不存在的会话及异常计数。
- 网络归档与实时设备使用不同工作区 ID；诊断的原 eventId/runId 保留，但导入运行独立命名，离线且不能被设备握手命中。恢复或重复导入不会被误当成实时 ACK 状态，监听仍由用户显式启动。
- 也可从“打开文件”导入标准诊断 v1 JSONL，按 runId 分成独立历史来源，不猜测与当前设备的关联。重复身份/序号、坏行或超限整次拒绝；ePay 私有 WARN/ERROR 文件结构尚无固定契约，不冒充标准 JSONL。
- P3 离线库上限调整为 12 会话/192 MiB 原文，实时网络仍为 8 会话、每个 8 MiB/10,000 条；诊断合计最多 8 运行、每运行 2,000 条/4 MiB。单个归档文件及展开总量最多 256 MiB，网络成员最多 64 MiB，诊断单行最多 128 KiB。超限明确失败，不静默截断。

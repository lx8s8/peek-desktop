## 归档 v1

- 归档为 ZIP，包含 `manifest.json`、`network/0.peek` 等网络文件、`diagnostics/0.jsonl` 等诊断文件；manifest 包含容器版本、网络/诊断版本、各成员 SHA-256、字节数、条数及网络关联与保留计数。不会归档配对 token。
- “保存完整归档”保存当前网络会话及其绑定诊断运行，或当前独立诊断运行；不受列表搜索、分组和时间过滤影响，只包含当前实际保留的数据。已淘汰的正文/日志不凭空补全，尚未取回的 remote 正文保持未加载。保存时还在同步的网络快照会标记该状态。
- 网络与诊断原始记录保留长数字、未知字段、重复 JSON key 和堆栈；LF 换行。ZIP 写入临时文件并 fsync，成功后原子替换；错误不破坏原文件。
- 导入先完整校验，容量不足或任一成员损坏时整组失败。成员名严格匹配约定，不解压到文件系统；拒绝多余/重复成员、未来版本、校验和不匹配、绑定不存在的会话及异常计数。
- 网络归档与实时设备使用不同工作区 ID；诊断的原 eventId/runId 保留，但导入运行独立命名，离线且不能被设备握手命中。恢复或重复导入不会被误当成实时 ACK 状态，监听仍由用户显式启动。
- 也可从“打开文件”导入标准诊断 v1 JSONL，按 runId 分成独立历史来源，不猜测与当前设备的关联。重复身份/序号、坏行或超限整次拒绝；ePay 私有 WARN/ERROR 文件结构尚无固定契约，不冒充标准 JSONL。
- P3 离线库上限调整为 12 会话/192 MiB 原文，实时网络仍为 8 会话、每个 8 MiB/10,000 条；诊断合计最多 8 运行、每运行 2,000 条/4 MiB。单个归档文件及展开总量最多 256 MiB，网络成员最多 64 MiB，诊断单行最多 128 KiB。超限明确失败，不静默截断。

## 导出边界

- 文件菜单与“导出与恢复”面板提供 HAR、全部当前日志 JSONL/文本，所选 300 条 JSONL 的既有命令继续可用。全部导出不受 300 行分页、选择、搜索或时间范围限制；取消文件对话框不写入目标。
- HAR 1.2 保留请求头和查询参数重复值；响应二进制使用 base64，原始正文元信息写入 `_peekBody`，缺失大小/正文及推断截断分别标记。没有采集的 HTTP 版本使用空字符串；未测可选阶段时间为 -1，必选阶段按格式写 0 并在 `_peek.unknownTimingFields` 标记未知，HAR time 为已知阶段之和，捕获的总时长另存 `_peek.durationMs`。不将未测时间解释为实际零耗时。参考 [HAR 1.2](https://w3c.github.io/web-performance/specs/HAR/Overview.html)。
- cURL 是供 POSIX shell 粘贴的命令文本，程序不会执行请求。逐参数引号保护单引号、美元符号、反引号和换行，正文用 `--data-raw` 避免前导 `@` 读取文件。支持完整文本和无文件 URL 编码表单；二进制、文件上传、未取回或截断正文明确拒绝。参考 [curl 手册](https://curl.se/docs/manpage.html)。
- 350 条原始诊断全部导出并重新导入通过；HAR 重复头、二进制、缺失正文及时间算式验证通过；用 shell 中的本地参数捕获函数验证 cURL 转义，不发送任何网络请求。

## 工作区恢复

- 默认关闭自动保存，可在“导出与恢复”开启；也可显式“立即保存工作区快照”。设置和两份快照位于应用数据目录的 `recovery/`，本机单实例持有文件锁，另一个实例只保留其正常工作区功能并显示恢复缓存不可用。
- 自动模式每 5 秒检查会话/远端版本变化，未变化跳过磁盘写入，正常退出补存。快照涵盖当前整个工作区，仍受单归档容量和离线库/诊断容量限制；超限显示错误并保留旧快照，不裁掉部分会话。最近一个检查周期及尚未加载的设备正文不承诺可恢复。
- 两个固定槽位轮换原子写入，最多两份 256 MiB 快照；加载后若有旧快照，先标记待恢复并暂停自动覆盖。用户可“恢复上次工作区”或“开始新的恢复记录”。空工作区不覆盖最后一个非空快照；“开始新记录”不直接删除旧槽位。
- 校验最新快照失败时尝试另一份；两份均损坏、容量不足或导入失败不改当前会话。每次启动只应用一次待恢复快照。恢复来源、网络原始设备/运行标识、诊断原始设备来源及保留计数随再归档继续保留。
- 恢复数据为离线副本，不重用 live key、不恢复设备连接、配对权限或实时协议 ACK。日志 SDK 的 ACK 依然表示内存接纳；后台快照不改变投递协议，崩溃时新实时会话仍可明确报告 SDK 无法重放的缺口。
- 回归覆盖默认关闭、配置保留、启动空窗口/待恢复不覆盖、重复恢复阻断、最新损坏回退、双份损坏保持现有工作区、单写入者锁、只清理托管目录中本程序遗留的临时文件、未变化跳过写入，以及新保存失败保留两份旧文件。全量 Rust 已通过 42 项常规测试；旧容量回归的硬编码 4 已随新容量改为使用边界常量，继续验证满库拒绝。

## 大会话与恢复锁范围

- 2026-11-16 单次合成探针：Apple M3 Pro、18 GiB RAM、macOS 27.2.1（26B131）、arm64、Rust 1.91.1，debug 构建，100,000 条请求。输入原文 39,899,202 字节，归档 1,526,361 字节，HAR 110,589,086 字节。导入 3,321.64 ms、归档保存 4,195.01 ms、归档回读 4,227.76 ms、HAR 导出 16,634.68 ms、恢复回读 3,920.44 ms；整个探针 37.17 秒。条数和查询结果回归一致。
- `/usr/bin/time -l` 对独立核心探针记录 maximum resident set size 274,120,704 字节、peak memory footprint 338,396,000 字节。此结果包含探针同时持有的输入、归档和恢复对象，不含 WebView，不代表桌面总内存、实时吞吐或 release 性能。
- 基于多秒级磁盘操作，恢复路径拆为“短锁捕获/整组提交”和“锁外编解码”：ZIP 保存、读取及校验不持有离线库或实时数据锁。新增回归证明捕获后可释放/修改工作区，之后仍保存捕获时的数据。磁盘写入前预检容量，拒绝超过空离线库可恢复范围的快照。
- 重现：`node scripts/generate-session.mjs <新路径.peek> 100000`，再 `cargo run --locked --manifest-path src-tauri/Cargo.toml --example archive_probe -- <路径.peek>`。探针使用临时目录，不修改用户恢复缓存。
- 真实官方 Flutter 客户端与 bridge 的扩展跨语言测试通过：实际取回的大正文、长整数/小数、4 条诊断原文和明确关联，经历归档和两份快照恢复后仍正确；恢复侧不监听、不连接，HAR 正文精度保持。

# P2：日志查看、时间线与双语菜单

记录日期：2026-11-13。本阶段增加筛选、异常分组、时间线、选择操作及中英文原生菜单。

## 完成内容

- 日志按时间、级别、来源、tag 和 emitter 筛选；不同视图保留各自过滤与选择
- 异常按指纹分组，可打开原始成员、堆栈、空堆栈和裁剪说明
- 时间线合并网络与诊断，共享时间范围，支持准确请求跳转和失效引用提示
- 跟随/暂停、键盘导航、多选、消息/堆栈/原文复制及所选 JSONL 导出
- 工具栏、快捷键、原生菜单及右键菜单共用命令调度和可用状态

分组次数按当前保留数据和过滤条件统计，原始事件不合并。时间线按墙钟时间排序；精确关联需要同一网络会话中仍保留的显式请求 ID。诊断与时间线每次最多查询 300 行，选择最多 300 条，复制最多 1 MiB。

## 菜单实现与修复

中英文使用同一组稳定命令 ID。工具栏和应用菜单使用当前工作区；右键捕获选择上下文，视图替换后旧处理器失效。菜单重建只保留最新版本，替换或卸载时释放原生资源。

原生验证发现两个问题：

1. 重建相同 ID 的菜单后，旧 Tauri 菜单释放会清理 JavaScript 点击通道。改为 Rust `on_menu_event` 向前端发送稳定命令 ID；右键用临时原生 ID 映射
2. Tauri 的菜单 popup 在跟踪期间持有资源表锁，导致 IPC 等待。改为 Rust 先取得菜单并释放锁，再弹出菜单

自动化回归覆盖重建路由、旧菜单失效和资源清理；原生验证另检查菜单展开时继续接收数据。

## 验证

当时通过 31 项前端测试、27 项 Rust 测试、跨语言回归、类型检查、格式、Clippy、前端及 macOS debug 构建。

macOS 窗口验证异常三次分组、原始成员、空堆栈、属性截断、消息/堆栈复制、JSONL 保存及导出行数。暂停跟随后仍接收日志，多选与键盘导航正常。有效引用可跳到 GET 200 请求；失效引用显示原因且不提供跳转按钮。

连续日志测试最初因示例使用 `warn` 而非协议的 `warning`，只收到 108 条。修正后实测 120 条全部 ACK（108 info / 12 warning）。菜单锁修复版保持操作菜单展开，再发送 120 条，接收数从 24 增至 120，ACK 从 120 增至 240，窗口持续响应。

当时重启丢失的 120 条已 ACK 内存记录显示为缺口；重启后新接收 126 条单独计数，没有计入重复或已接收数。磁盘恢复随后在 P3 实现。

## 本地调试签名与钥匙串

通过 `codesign -d -r- --verbose=2` 检查，本地 debug `.app` 使用 ad-hoc 签名，没有 TeamIdentifier，代码要求绑定当前 cdhash。重编译改变哈希后，macOS 可能再次询问是否允许访问原有 Keychain 条目；这不表示程序主动删除了配对。

Apple 的 [TN3127](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)说明了 ad-hoc 身份与具体代码版本的关系。发布准备需使用稳定的 Apple Development 或 Developer ID 签名，并验证升级后原凭据访问。本阶段未修改证书或钥匙串授权规则。

Windows、物理手机和完整性能矩阵仍需验证，见[待办](待办.md)。

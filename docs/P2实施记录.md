## 统计与关联边界

- 异常指纹包含类型、消息和原始堆栈，只影响展示；次数与首次/最近时间按当前保留窗口及过滤条件统计，原始事件不会合并或重写。接收、去重、缺口和淘汰仍使用 P1 的独立计数。
- 时间线按事件墙钟时间排序，不推断跨 emitter 的因果关系；字符串序号保留原样。只有准确绑定的同一网络会话中明确引用且仍存在的请求显示显式关联；引用已淘汰或不存在时标明不可用。
- 列表最多返回 300 行元信息，详情按选中记录加载。时间线只快照摘要与共享搜索索引，释放诊断锁后完成网络合并和排序。
- 选中诊断事件最多 300 条。原始 JSONL 导出在后台原子写入，不重新序列化原始事件；复制内容最多 1 MiB，超限明确失败。
- 完整 `.peekbundle`、磁盘历史与恢复仍属于 P3；本阶段不将内存中的保留窗口描述成全部历史。

## 菜单与操作约定

- 文件、编辑、视图、连接、语言、窗口、帮助菜单使用同一份中英文词条。自定义命令 ID 保持稳定，语言切换只改变标签；系统预定义操作遵循各平台支持情况。
- `session.open` / `session.save` / `session.close` 对应打开、保存网络和关闭已离线会话；在线会话关闭命令禁用。网络保存明确标为 `.peek`，诊断选中导出使用 `diagnostics.export` 和 JSONL。
- `view.network` / `view.logs` / `view.exceptions` / `view.timeline` 使用 Cmd/Ctrl 1–4；Cmd/Ctrl F 搜索当前视图，Shift F 切换跟随，Shift D 切换主题，Shift L 切换语言。
- Cmd/Ctrl Shift C 复制所选消息，Alt C 复制所选堆栈，Shift S 导出所选事件；标准文本剪切/复制/粘贴保留原生行为。表格内方向键、Home/End、PageUp/PageDown 导航；Shift 连选、Cmd/Ctrl 点选多选，Cmd/Ctrl A 选择当前加载窗口（最多 300 条），Delete/Esc 取消选择，不删除采集事件。
- 命令调度会再次核对当前可用状态，应用菜单使用当前工作区；右键菜单捕获选择上下文，不能调用已替换视图的处理器。连接弹窗期间禁用会冲突的工作区操作。快速语言切换只安装最新菜单，显式关闭 JavaScript 菜单引用；右键菜单最多保留一个，替换或卸载时释放。
- 原生窗口验收发现：重建相同 ID 的菜单后，Tauri 旧菜单释放会清理按 ID 注册的 JavaScript 点击通道，出现标签更新但自定义操作不执行。现改为 Rust `on_menu_event` 向主窗口统一发送命令 ID，不使用逐条目的点击通道；右键使用独立临时原生 ID 映射到稳定命令，并在替换/卸载时清理映射。自动回归覆盖重建后的命令路由、旧右键失效与资源释放。
- 进一步原生验收发现 Tauri `plugin:menu|popup` 在菜单跟踪期间持有 Webview 资源表锁；线程采样确认菜单内嵌事件循环中的其他 IPC 等待同一锁，导致窗口挂起。现通过自有 `popup_context_menu` 先取出菜单的共享引用并释放资源表锁，再在阻塞任务中调用原生弹出；菜单资源与命令映射继续按原生命周期释放。右键使用明确坐标，另提供“操作菜单”按钮供键盘和辅助功能打开同一菜单。
- 关联请求按钮会先校验所绑定网络会话中的记录是否保留；失效引用直接显示不可用，不先尝试跳转。网络重同步或淘汰后重新校验，旧异步结果不能恢复错误入口；临时读取失败可以重试。新增两项回归覆盖失效引用和网络版本切换竞态。
- 复制通过 Rust 的系统剪贴板接口完成，前端仅保留浏览器预览备用路径；不读取用户剪贴板。写入与复制内容有 1 MiB 上限，超限可选择 JSONL 导出。
- 原生菜单及引用管理依据 [Tauri 菜单文档](https://v2.tauri.app/learn/window-menu/)，系统剪贴板使用锁定的 `tauri-plugin-clipboard-manager 2.5.0`，见 [官方剪贴板接口](https://v2.tauri.app/plugin/clipboard/)。

## 本地调试包反复提示钥匙串的原因

实际使用 `codesign -d -r- --verbose=2` 检查当前 `.app`：它是链接器生成的 `ad-hoc` 签名，没有 TeamIdentifier，designated requirement 直接绑定当前 `cdhash`。重新编译代码后哈希变化，新的二进制不再匹配此前被允许的代码身份；因此此前点击“始终允许”后，新构建仍可能再次要求系统授权。这不是配对凭据被应用主动清除。

Apple 的 [TN3127 签名身份说明](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements) 明确说明，ad-hoc 签名的身份只绑定到特定代码版本，macOS 无法据此跨构建稳定跟踪授权。长期应使用固定的 Apple Development 或 Developer ID 签名证书和稳定签名标识；本轮只核验并记录原因，没有修改证书或钥匙串授权规则。验收结束时保留当前已授权的运行进程，不再为文档修改重启程序。

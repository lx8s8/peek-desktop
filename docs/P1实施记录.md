# P1：设备配对、实时网络与日志同步

记录日期：2026-11-13。本阶段在离线工作区上接入设备监听、标准网络协议及 Flutter 日志 bridge。SDK 后续已拆到独立的 MIT 仓库，当前接入见 [SDK 文档](https://github.com/lx8s8/peek-flutter-sdk)。

## 完成内容

| 部分 | 实现 |
| --- | --- |
| 配对 | 四位码、180 秒有效、一次性消费、五次错误轮换、凭据写入失败回滚 |
| 授权 | 系统凭据存储，网络与诊断分别授权，关闭诊断和忘记设备 |
| 网络 | WebSocket、可选 mDNS、历史 staging、实时增删改、重连隔离和正文取回 |
| 诊断 | 能力探测、同设备会话绑定、批次/ACK、去重和 gap |
| SDK | Talker 订阅、原始堆栈、脱敏、有界队列、重连和生命周期 |
| 桌面 | 监听启停、配对设置、设备状态、实时网络与基础日志查看 |

监听默认关闭，最多配对 4 个设备。网络侧最多 16 个握手/连接、8 个运行会话；每会话 10,000 条 / 8 MiB，重同步 staging 另有同等预算。正文在途最多 32 个、每连接发送队列 16 个、正文超时 8 秒；HTTP 头最多 8 KiB，WebSocket 消息最多 8 MiB。

## 自动化验证

当时通过 11 项前端测试、22 项常规 Rust 测试、SDK 7 项 Flutter 测试，及分析、格式、Clippy、前端构建。Rust 测试覆盖真实 TCP/WebSocket、配对回滚、绑定/撤销、重连旧帧、正文关联、序号、缺口及容量淘汰。

额外的 Rust / Dart 联合测试使用真实 `PeekRemote 2.1.1`，覆盖配对、网络历史/更新、凭据重连、4 条日志累计 ACK、脱敏、原始堆栈、超过 6 KiB 的正文及 `.peek` 导出。测试使用临时端口和内存凭据，命令见[开发指南](../CONTRIBUTING.md#sdk-联合测试)。

## macOS 操作验证

- Tauri debug 应用和 Flutter 示例均构建成功；实际配对后网络为 connected、日志为 ready
- 发送 5 条测试日志后待发数为 0、ACK 为 5；关闭诊断时网络继续收第 2 条请求，重新授权并重试后 ACK 到 6
- WKWebView 显示完整长整数、高精度小数和 Dart 原始堆栈；配对成功后四位码消失
- 重编译实例经用户完成 Keychain 授权后恢复原配对，客户端不输入新码即可连接两路；发送请求和日志后 ACK 为 2、待发为 0
- `dns-sd` 发现 `_peek._tcp.local.`，端口、协议版本和 server identity 正确；官方 Flutter `remote.discover()` 可发现、配对并同步两路数据
- 两个内存凭据服务按 A → B → A 切换，返回 A 无需配对码，两路连接回到 A，B 保持监听

## 保留说明

P1 的数据只在内存中保留，ACK 表示内存接纳。每诊断运行最多 16 个 emitter、最近 64 个 gap 范围；桌面重启丢失的已 ACK 日志可能无法重放。P3 随后增加归档与恢复快照，但没有修改 ACK 语义。

本阶段未验证 Windows、物理手机、跨物理电脑、多网卡切换及休眠。后续日志查看见 [P2](P2实施记录.md)，文件与恢复见 [P3](P3实施记录.md)，当前未完成项见[待办](待办.md)。

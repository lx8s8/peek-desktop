# 设备连接

## 首次连接

1. 电脑和手机连接到可互通的局域网
2. 打开 Peek Desktop 的“设备连接”，默认选择“局域网设备”；核对本机地址后启动监听
3. 生成配对码，选择手机可达的网卡地址
4. App 扫描二维码，或填写电脑地址和四位配对码
5. 需要日志时，在配对设置中允许诊断同步

配对成功后，App 的网络连接应为 `connected`；接入日志包且获准同步后，诊断状态应为 `ready`。默认端口为 `9741`。

## 应该使用哪个地址

| 地址 | 用法 |
| --- | --- |
| 电脑的局域网 IP，如 `192.168.1.8` | 手机或其他电脑连接时使用 |
| `127.0.0.1` | 客户端和桌面服务运行在同一台电脑时使用 |
| `0.0.0.0` | 服务端监听所有 IPv4 网卡的配置值，不作为连接目标 |

打开连接页即可查看和复制本机地址，无需先启动监听或读取配对凭据。页面每 10 秒、重新回到窗口时刷新，也可手动刷新；更改端口后，显示地址随之更新。

多网卡电脑会列出多个地址，优先显示 Wi-Fi、以太网，排除常见隧道、虚拟网卡以及回环、链路本地地址。选择与手机网络可达的地址后，二维码随之更新。网卡地址不代表连通性检查结果；公司网络的隔离策略仍可能阻止设备互访。

## 扫码与配对链接

二维码包含地址、端口、桌面身份、四位配对码和过期时间。配对码 180 秒有效，成功一次后失效；过期后在电脑上重新生成。

App 通过 [`peek_desktop_connect`](https://github.com/lx8s8/peek-flutter-sdk/tree/main/packages/peek_desktop_connect) 的 `onScan` 接入自己的扫码页面。SDK 校验解码文本并连接；也可以直接粘贴配对链接。二维码不包含长期设备凭据，App 无需注册全局深链。

## 共享测试机

一台手机可保留多台电脑的配对，每次选择一台连接。已配对电脑记录在 App 中，按 `serverId` 区分，IP 只保存最近地址。电脑 IP 改变后，可从发现列表选择同一身份的新地址。

点击历史记录可免码连接；“忘记这台电脑”删除对应本地凭据和历史，不影响其他电脑。桌面“忘记设备”会撤销该手机在本机的授权，下次连接需重新配对。

切换电脑时，日志 SDK 清空旧目标的待发队列；网络客户端会把当前 Peek store 中保留的请求同步给新目标。共享测试机在切换人员或账号时，应由 App 清理对应账号的本地诊断历史。

## Bonjour 发现

桌面在局域网模式下开启 mDNS 后，以 `_peek._tcp` 发布服务。App 点击“搜索局域网电脑”查询并选择结果。iOS 诊断构建需要局域网用途说明和 Bonjour 服务声明，配置见 [SDK 连接指南](https://github.com/lx8s8/peek-flutter-sdk/tree/main/packages/peek_desktop_connect#地址与权限)。

发现依赖组播。同一 Wi-Fi 下仍无结果时，可直接扫码或输入 IP，不必等待发现成功。

## 常见问题

| 现象 | 检查方法 |
| --- | --- |
| 找不到电脑 | 确认桌面已启动监听和 mDNS、App 已允许局域网权限；公司网络可能屏蔽组播 |
| 扫码后连不上 | 确认选中的网卡地址可达、端口未被防火墙阻止；过期时重新生成二维码 |
| 已配对仍要求配对码 | 检查桌面是否撤销设备、App 是否清除了本地存储，以及是否选中了原电脑身份 |
| 网络正常但无日志 | 确认已接入 bridge、允许诊断同步；重新授权后调用 `bridge.reconnect()` |
| 本地重新编译后又提示钥匙串 | 当前 debug 应用使用临时签名，重编译可能改变代码身份，详见 [P2 记录](P2实施记录.md#本地调试签名与钥匙串) |

本机已验证官方发现、两套独立服务间的配对切换和诊断同步。手机相机、移动端权限及跨物理电脑切换列在[待办](待办.md)中。

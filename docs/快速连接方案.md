# 局域网与共享测试机快速连接

## 地址与桌面端二维码

`127.0.0.1` 仅供电脑上的同机示例使用。真机应在桌面“设备连接”选择“局域网设备”，启动监听后填写实际网卡 IP，例如 `192.168.1.8:9741`。`0.0.0.0` 是监听范围，不能作为客户端目标；默认仍由用户显式启动监听。Bonjour/mDNS 可减少手工输入，但跨网段或禁用组播的网络仍需手动地址。

局域网模式生成四位配对码后，会显示对应实际 IP 的二维码。多网卡可选择不同地址；二维码成功配对一次或 180 秒到期后失效，停止监听后不显示。不依赖远程二维码服务，不包含长期 token。剪贴板中的旧链接也受服务端一次性配对规则限制。

链接格式：`peek-desktop://pair?v=1&host=192.168.1.8&port=9741&serverId=<桌面身份>&code=<四位码>&expiresAt=<Unix秒>`。扫码是 App 诊断入口内的功能；此阶段不注册操作系统全局深链。二维码中 serverId 用于选择该桌面的官方凭据，服务端仍必须校验配对码。

## 插件边界

连接入口已独立为私有 [`peek_desktop_connect`](../sdk/packages/peek_desktop_connect/README.md)，供官方网络客户端和 `peek_desktop_bridge` 日志通道共用。它接收 App 已创建的同一个 `PeekRemote`，负责发现、历史列表、地址/二维码解析及连接 UI；日志包继续负责 Talker 转换、脱敏、队列和 ACK。

历史以 `serverId` 为键，IP 只是最近地址。官方 `PeekRemoteMemory` 已能按桌面身份保存多份 token，但只公开最后一台桌面的元信息；新包只补历史显示元信息，不复制 token。每次选择一个目标，切换时结束旧连接；同时广播到多台桌面需单独设计连接、队列和授权，不能仅创建多个日志订阅。

扫码相机由宿主 App 提供回调，复用已有扫码能力，避免日志包引入相机权限或扫码插件。诊断正式包隔离仍由宿主编译期控制；关闭时不得创建客户端、读取配对历史或启动发现。

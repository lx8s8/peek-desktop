# 桌面打包与发布

## 安装与升级

正式版本发布在 [GitHub Releases](https://github.com/lx8s8/peek-desktop/releases/latest)。

| 平台 | 产物 | 安装方式 |
| --- | --- | --- |
| macOS 11+，Apple Silicon | `macos-arm64-unsigned.dmg` | 挂载后拖到 Applications |
| macOS 11+，Intel | `macos-x64-unsigned.dmg` | 同上 |
| Windows x64 | `windows-x64-unsigned.exe` | 当前用户安装，无需管理员权限 |

应用名称为 Peek Desktop，发布者和 Git 作者为 `kasen`。标识保持 `local.peek.desktop`，升级时不修改配对服务或应用数据目录。

macOS 使用 ad-hoc 签名，不使用开发或分发证书，不公证；Windows 安装器和应用均不签名。无证书是当前正式发布方式，与 GitHub 的正式版本或预发行标记分别管理。macOS 首次运行可参考 [Apple 打开应用说明](https://support.apple.com/zh-cn/102445)，Windows 可能显示未知发布者提示。

macOS 用新应用替换旧应用，Windows 运行新版安装器；升级保留配对和恢复目录，Windows 阻止降级。更换 ad-hoc 应用后，macOS 可能再次询问钥匙串访问授权。

## 关于与检查更新

工具栏信息按钮、macOS 应用菜单或 Windows 帮助菜单可打开“关于 Peek Desktop”，查看版本、平台、作者、项目与反馈地址、SDK 和上游项目，以及随包附带的 MIT 和第三方许可原文。

从关于页面或菜单选择“检查更新”。应用请求 GitHub 的最新正式 Release，按语义版本比较，并在发现新版且存在受信任的 `latest.json` 更新清单时启用应用内更新：

- 点击“下载并安装，完成后重启”后会实时显示下载进度，下载阶段随时可点击“取消下载”；
- 下载完成后自动通过应用内置的 Minisign 公钥校验更新包完整性及绑定的版本号（`requireSignedVersion: true`）；
- 进入安装阶段后不可取消，应用会先保存当前工作区恢复快照并停止远端监听，覆盖安装完成后自动重启；
- 若目标版本未提供 `latest.json`（如旧版 Release）或安装失败，仍保留外部下载与 Release 页面入口兜底。

检查只读取公开 Release，不上传工作区、日志或配对数据。请求超时或达到 GitHub 频率限制时显示错误并允许重试；成功结果在进程内缓存 60 秒。没有后台静默下载或强制自动安装。

首次集成应用内更新的版本需手动下载安装一次；后续版本即可直接在应用内完成下载、校验、安装与重启。

## 本地打包

按[开发指南](../CONTRIBUTING.md)准备环境：

```sh
pnpm install --frozen-lockfile
pnpm release:check
pnpm release:test
pnpm check
pnpm test
pnpm package:local
```

所有打包入口固定使用 `unsigned`。默认本机构建不生成更新签名产物，脚本主动清除继承的代码签名与更新签名凭据，macOS 明确指定 `-`，Windows 明确清空签名配置。

```sh
# 只检查配置
pnpm package:local --check
# 本地 Debug 安装包
pnpm package:local --debug
# Intel 交叉构建，需安装对应 Rust target
pnpm package:local --target x86_64-apple-darwin
```

`release-artifacts/` 保存安装器、manifest 和 SHA-256。manifest 记录版本、源码、平台、架构、脏工作区及签名/公证状态。正式发布只接纳 Release、干净源码以及三个平台来自同一提交的产物。

## 更新签名密钥配置

正式标签发布及草稿发布使用独立的 Tauri updater Minisign 密钥对，公钥嵌入 `src-tauri/tauri.conf.json` 的 `plugins.updater.pubkey`，私钥仅存放在仓库外与 GitHub Actions Secret：

```sh
# 首次初始化（默认拒绝覆盖已有身份，保存至 ~/.config/peek-desktop/updater/）
pnpm updater:key
```

将生成的 `github-updater-secret.json` 内容写入仓库 Actions Secret `PEEK_DESKTOP_UPDATER`（JSON 包含 `privateKey` 和 `password`）。后续版本必须持续沿用同一密钥对，不能临时重建替换已分发版本的验证公钥。

## 发布新版本

1. 确认 GitHub 仓库已配置 Actions Secret `PEEK_DESKTOP_UPDATER`
2. 同步 `package.json`、`src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json` 的 `x.y.z` 版本，更新 Cargo lock
3. 在 `docs/releases/vX.Y.Z.md` 编写发布说明，更新 `CHANGELOG.md`
4. 完成检查并用中文提交，作者使用 kasen
5. 推送 `vX.Y.Z` 标签；标签必须与代码版本一致
6. 等待三平台全部完成构建、测试、更新签名校验及安装包验证，工作流随后公开正式 Release

[桌面工作流](../.github/workflows/package-desktop.yml)也在 main 代码变更、PR 时检查和打包，这些运行不读取签名 Secret，只上传 artifacts，不公开版本。手动运行的 `create_draft` 默认关闭，开启时会使用 `PEEK_DESKTOP_UPDATER` 生成草稿产物与 `latest.json`。

标签发布先创建草稿，上传两个 DMG、一个 EXE、两份 macOS `.app.tar.gz` 更新归档、`latest.json`、三份 manifest 和 `SHA256SUMS.txt`（不上传裸 `.sig` 文件，签名已校验并内嵌于 `latest.json`），再公开并设为 latest。缺平台、版本/提交不一致、脏源码、更新签名或哈希不符时停止。已有公开版本不覆盖；同一源码的未完成草稿可重试上传。

只有发布 job 获得 GitHub `contents: write`；普通 PR 与主分支构建不读取任何签名密钥。Actions 固定提交 SHA，Release 附件长期保留，临时 artifacts 保留 7 天。

## Windows 免费签名

[SignPath Foundation](https://signpath.org/)为符合条件的开源项目提供免费签名。其[申请条件](https://signpath.org/terms.html)要求项目持续维护、已有公开发布等，并需通过审核和配置受控构建流程。

目前没有已获批的 SignPath 项目或凭据，本次使用未签名包。后续获批时再接入 Windows 签名，不影响当前 macOS 无证书方案。

## 文件关联与许可

`.peek` 注册为查看类型，`.peekbundle` 注册为 Peek Desktop 归档；`.jsonl` 使用应用内“打开文件”，不抢占通用关联。macOS Finder 和 Windows 文件参数均支持冷启动与热打开，一次最多排队 32 个文件。

代码采用 [MIT](../LICENSE)。`pnpm notices:generate` 依据锁定依赖生成 [第三方声明](../THIRD_PARTY_NOTICES.md)。两份原文随应用附带，并可在关于页面离线查看；Windows 安装器显示 MIT 许可页，macOS 不添加挂载协议页。

# 桌面打包与发布

## 安装包

| 平台 | 产物 | 安装方式 |
| --- | --- | --- |
| macOS Apple Silicon | arm64 DMG | 挂载后拖到 Applications |
| macOS Intel | x64 DMG | 同上 |
| Windows x64 | NSIS `.exe` | 当前用户安装，无需管理员权限 |

应用名称为 Peek Desktop，发布者和 Git 提交作者使用 `kasen`。Bundle identifier 保持 `local.peek.desktop`，后续版本不随仓库或显示名称改变，以保留现有配对服务和工作区目录。

macOS 的最低配置为 11.0。Windows 安装器提供简体中文、英文，并安装需要的 WebView2 引导组件；网络受限时需预先安装 WebView2。Windows 的界面和设备互操作仍需在实际机器上补验。

## 本地打包

先按[开发指南](../CONTRIBUTING.md)安装工具并完成检查：

```bash
pnpm install --frozen-lockfile
pnpm release:check
pnpm release:test
pnpm check
pnpm test
pnpm package:local
```

`package:local` 生成 Release 预览包：macOS 显式使用 ad-hoc 签名，Windows 不签名。它适合本地测试，不包含可信发布者签名和 macOS 公证。

输出位于 `release-artifacts/`，包含安装包、构建清单和 SHA-256。文件名带版本、平台、架构和签名模式。清单记录源码提交、未提交修改、构建类型和签名/公证状态；不会复制配对凭据或用户日志。

```bash
# 只检查构建配置，不编译
pnpm package:local --check
# 开发调试用安装包
pnpm package:local --debug
# Intel macOS 交叉构建，需先安装对应 Rust target
pnpm package:local --target x86_64-apple-darwin
```

图标源文件为 [peek-desktop.svg](../assets/peek-desktop.svg)，执行 `pnpm icons:generate` 重新生成桌面图标。

## macOS 稳定签名

本地长期调试可使用明确指定的 Apple Development 身份：

```bash
pnpm package:development --check
pnpm package:development
```

运行前设置 `APPLE_SIGNING_IDENTITY` 为自己的完整 `Apple Development: ...` 证书名称。脚本不会自动选择本机已有证书，也不会把身份写入 Git。该模式不做公证，不作为对外分发包。

对外分发使用：

```bash
pnpm package:signed --check
pnpm package:signed
```

需要 `Developer ID Application: ...` 签名身份，以及以下任意一组公证配置：

- `APPLE_API_KEY`、`APPLE_API_ISSUER`、`APPLE_API_KEY_PATH`
- `APPLE_ID`、`APPLE_PASSWORD`（App 专用密码）、`APPLE_TEAM_ID`

签名私钥必须已在本机可用；CI 则从专用 P12 导入。正式包要求干净的已提交源码和 Release 构建。构建后检查应用签名、实际证书类型、版本和文件关联；Tauri 公证应用，脚本额外公证并装订最终 DMG，再校验票据。

首次用新身份访问旧 Keychain 条目仍可能出现系统询问；完成授权后，固定 Bundle identifier 和签名证书可让后续构建维持代码身份。ad-hoc 每次重新编译的 cdhash 不稳定，不能代替证书签名。证书更换和续期仍应做升级验收。

参考：[Tauri macOS 签名与公证](https://v2.tauri.app/distribute/sign/macos/)。

## Windows 签名

本地将代码签名证书导入当前用户证书库，设置 `WINDOWS_CERTIFICATE_THUMBPRINT` 后运行 `pnpm package:signed`。使用 SHA-256 和 RFC 3161 时间戳；构建后应用及安装器都必须通过 Authenticode 验证。

CI 使用 `WINDOWS_CERTIFICATE`（PFX 的 Base64）与 `WINDOWS_CERTIFICATE_PASSWORD`。导入脚本只允许运行于 GitHub 临时运行器，选择一个带私钥且未过期的代码签名证书，构建后临时证书文件删除。

没有证书时只生成明确标注的 preview 包。正式模式缺失配置会失败，不退回未签名产物。参考：[Tauri Windows 签名](https://v2.tauri.app/distribute/sign/windows/)。

## GitHub Actions

[桌面检查与打包](../.github/workflows/package-desktop.yml)在代码变更时执行：

1. 前端检查、测试、构建和版本检查
2. macOS / Windows 的 Rust 测试、格式和 Clippy
3. 构建 macOS arm64、macOS x64、Windows x64 预览安装包
4. macOS 验签、DMG 挂载复制及许可文件检查；Windows 静默安装、许可文件、文件关联和卸载测试
5. 上传 Actions artifacts，保留 7 天

手动运行工作流可选择 `preview` 或 `signed`。`create_draft` 默认关闭；开启后需要三个平台全部成功，并再次核对提交、版本、模式和 SHA-256 才创建草稿。preview 草稿标为 prerelease，正式模式要求全部签名和公证通过。工作流不会自动公开草稿。

GitHub 仓库 Secrets 配置：

| Secret | 内容 |
| --- | --- |
| `APPLE_CERTIFICATE` | Developer ID Application P12 的 Base64 |
| `APPLE_CERTIFICATE_PASSWORD` | P12 导出密码 |
| `APPLE_SIGNING_IDENTITY` | 完整 Developer ID Application 名称 |
| `APPLE_API_KEY` | App Store Connect Key ID |
| `APPLE_API_ISSUER` | Issuer ID |
| `APPLE_API_PRIVATE_KEY` | P8 文件内容 |
| `WINDOWS_CERTIFICATE` | Windows 代码签名 PFX 的 Base64 |
| `WINDOWS_CERTIFICATE_PASSWORD` | PFX 导出密码 |

签名材料不进仓库。CI 使用临时文件并清理；Actions 固定提交 SHA，只有创建草稿的 job 拥有仓库写权限。

## 版本与升级

`package.json`、`src-tauri/Cargo.toml` 和 `tauri.conf.json` 必须使用相同的 `x.y.z` 版本。`pnpm release:check vX.Y.Z` 可核对标签；工作流使用实际构建提交创建草稿，已有版本不覆盖。

当前采用手动下载升级：macOS 用新应用替换 Applications 中的旧应用，Windows 运行较新版本安装器。不要在升级时修改应用标识、配对服务名或恢复目录。Windows 安装器阻止降级。自动更新器、更新签名密钥及服务器尚未接入。

发布前核对安装包、SHA-256、系统最低版本及已完成验证。签名和公证的结果以构建清单及平台验证为准，实际完成情况见 [P4 记录](P4实施记录.md)。

## 文件关联

`.peek` 注册为查看类型，`.peekbundle` 注册为 Peek Desktop 归档。通用 `.jsonl` 不抢占系统关联，使用应用“打开文件”或显式文件参数导入。

macOS 支持 Finder 打开文件，Windows 支持资源管理器双击；应用已运行时把新文件交给原窗口。一次最多排队 32 个，导入和保存期间等待。扩展名、文件类型及内容均校验；坏文件提示后继续处理其余文件，取消会清空余下队列。

## 许可文件

桌面代码采用 [MIT](../LICENSE)。`THIRD_PARTY_NOTICES.md` 汇总锁定组件的许可、作者和来源；生成命令为 `pnpm notices:generate`。Windows 安装器显示 MIT 许可页；macOS 不增加挂载确认协议。两端安装包均将两份文件放入应用资源的 `licenses/`，macOS 验证原文一致，Windows 安装验收检查文件存在。
